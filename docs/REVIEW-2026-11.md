# Rada — full review, 1 Nov 2026

State reviewed: `main` @ 798ae94 (M0–M3 delivered July 2026, untouched since).
Method: line-by-line read of all 25 source files, CI workflow, schema, spec; re-verification of external dependencies (Neurokõne API format confirmed; Harno 2026 dates expired, 2027 registration opens 01.01.2027).

---

## 1. Verdict in one paragraph

The architecture is sound and the hard infrastructure problems are solved: local-first Drift DB with migrations, one Flutter codebase producing real macOS + Android builds, a fully automated push→CI→installable loop, bilingual UI, domain logic under test. What's wrong is concentrated in a few places that make the *delivered builds* less capable than the code suggests — most seriously, **sync can never work in any CI-built binary**, Android updates will refuse to install over the previous version, and the Claude model default is now retired. None of these are deep; all are fixable in one pass. Beyond bugs, the biggest learning gap is that the app has **no vocabulary system at all** — the single highest-leverage learning feature for 0→B1 is still unbuilt (M5).

## 2. Bugs — things that are actually broken

### P0 — breaks real use

| # | Where | Problem | Fix |
|---|---|---|---|
| B1 | `main.dart`, CI | Supabase URL/key come from a compile-time `.env`. CI copies the **empty** `.env.example`, so every .dmg/.apk ever delivered has `syncConfigured = false`. The user cannot fix this without building locally. | Move Supabase URL + key into in-app Settings (settings_kv), initialize Supabase lazily at runtime. Drop `.env` entirely. |
| B2 | CI `build-android` | `flutter build apk --release` with no signing config signs with the runner's **freshly generated debug keystore** → a different key every build → Android rejects updates ("app not installed"); user must uninstall each time, losing local data. | Commit a dev keystore (personal project) or store one in a GitHub secret; wire `signingConfigs.release`. |
| B3 | `speech_config.dart` | Default Anthropic model `claude-sonnet-4-5` is retired as of Nov 2026 → cloud mode fails with 404 on first use. Model string is also **not editable** in the speech settings dialog. | Default to `claude-sonnet-5-5` (or `claude-haiku-5-5` for cost); add model field to dialog. |
| B4 | `sync_service.dart` | All timestamps pushed as local-time ISO strings **without timezone** (`toIso8601String()` on a local `DateTime`). Postgres `timestamptz` reads them as UTC → every row is off by the Estonian offset (+2/+3 h). Consequences: LWW decisions skewed by hours (possible ping-pong between devices), and `activity_log.date` midnight shifts to the previous day on the other device → heat-map/streak disagree between Mac and phone. | `toUtc().toIso8601String()` on push; `.toLocal()` after parse on pull; store `activity_log.date` as a `YYYY-MM-DD` string instead of timestamptz. |
| B5 | `repo.dart`, `trail_screen.dart` | Default exam date `2026-11-08` is a week away with registration closed since 01.10. Registration deadline is computed as `examDate − 36 days`, which is a guess; real deadlines are fixed quarterly dates. | Remove the hard default; show "pick a date" until set. Add an `exam_dates` seed (official 2027 dates once published 01.01.2027) with real registration deadlines, selectable from a list. |

### P1 — wrong, but survivable

| # | Where | Problem | Fix |
|---|---|---|---|
| B6 | `app.dart` | Theme choice is not persisted — resets to Vaikus on every launch. | Save/load `theme` in settings_kv. |
| B7 | `course_webview_screen.dart` | Study minutes are logged in `dispose()` (fire-and-forget) while `TrailScreen` calls `_refresh()` immediately after pop → quest bar/streak often don't update until the next refresh. | Return elapsed seconds via `Navigator.pop(result)` and log in the caller before refreshing. |
| B8 | `sync_service.dart` | Sync is manual-only (button). Spec §9 says push on write / pull on focus. Only `progress_entries` + `activity_log` sync; `mock_exams`, `answer_keys`, `practice_sessions`, `exam_plans` do not → mock history and answer keys exist on one device only. | Auto-sync on launch + resume when configured; extend to the four tables (same LWW pattern). |
| B9 | CI | Every push to `main` triggers a ~12 min macOS build. The repo is **public** (confirmed 1 Nov: anonymous read works), so Actions minutes are free — no cost issue. But public means the `dist-*` branches with installables and any future committed keystore are world-readable. | Keep public (nothing secret is committed; keep it that way — a committed dev keystore is acceptable only because nobody else distributes this app). Still worth gating macOS builds to `workflow_dispatch`/tags to cut noise. |
| B10 | `.gitignore`, CI | Platform folders (`android/`, `macos/`) are regenerated by `flutter create` on every CI run and then patched with `sed`/`PlistBuddy`. Works, but brittle and it's why B2 exists. | Commit `android/` and `macos/` now that native config has stabilized; delete the patch steps. |
| B11 | `converse_tab.dart` | Conversation history grows unbounded and is sent whole on every turn (token cost, eventual context errors). | Cap to last ~20 messages. |
| B12 | `seed_loader.dart` | `seedExamAssetsIfEmpty` seeds once; URL changes never propagate. | Version the seed (`seed_version` setting) and upsert on bump. |
| B13 | Access | The July PAT has been **revoked** (good — push fails with auth error; reads work because the repo is public). | A new fine-grained token (Contents: read/write, this repo only) is needed before any fix pass can be pushed. |

### P2 — cosmetic / robustness

- `loadTrail` orders courses by `levelRange` string (`'0-A2' < 'A2-B1'` works by accident). Add an explicit `ord` column.
- Mock timer limits (15/20 min) are arbitrary; make configurable per section.
- Webview time logging counts idle time as study time; add an idle cutoff (no interaction for 10 min → stop counting).
- `vault_screen` on macOS opens PDFs via `launchUrl(file://)` — should work from the sandbox container, but unverified at runtime.
- Anthropic key stored in plain SQLite (`settings_kv`); move to `flutter_secure_storage` (already planned in spec).

## 4. Design critique — what I'd change knowing what we know now

1. **Vocabulary is the missing engine.** Every other feature is a wrapper around external content (Keeleklikk) or practice (speech). Nothing in the app *teaches* when you're offline on the phone for 10 minutes. An FSRS deck seeded per Keeleklikk chapter (the chapter themes are known: greetings, family, shopping, time, food, health, work…) plus corrections from the tutor would be the single biggest motivational and learning win. Promote M5's vocab work to the next milestone.

2. **Config belongs in the app, not the build.** Any value the user must supply (Supabase, API keys, server URLs) must be enterable in-app, because the user consumes CI binaries and never builds. B1 is the symptom; the principle should be applied everywhere (it already is for speech settings).

3. **Stop regenerating native projects in CI.** Commit them. It removes a class of fragility (B2, B10) and lets us set bundle ID, app name ("Rada" instead of "rada"), icon, and signing properly.

4. **The exam timeline has moved.** On 1 Nov 2026 at level ~0, the realistic target is a **Q2–Q3 2027** sitting (registration opens 01.01.2027). The app should model the real quarterly calendar rather than a free date picker with a guessed deadline.

5. **Honest signal on speech scoring.** Current pronunciation scoring = ASR word match. It's labeled honestly in the UI; keep it that way and don't let it drift into "pronunciation score" language.

6. **Conversation mode should feed everything else.** Tutor corrections → SRS cards; conversation minutes → streak (already); recurring error types → a "weak spots" stat on the dashboard. The data model supports all of it.

## 5. What is good and should not be touched

- Local-first design with Drift + explicit migrations (v1→v2→v3 chain works for upgraders).
- Single codebase, both targets, real installables delivered through git branches — the CI feedback loop is unusual and works.
- Domain logic (streak rules, word alignment) is pure Dart with tests; keep adding tests there.
- Bilingual UI with a graduation mode is pedagogically right.
- Hybrid LLM with "local corrections unverified" labeling — correct intellectual honesty.
